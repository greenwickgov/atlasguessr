# AtlasRush hosting on Render

The repository's `render.yaml` runs the existing Go/Next.js application as one
single-instance Docker web service with a managed PostgreSQL database in Singapore.
It does not use Convex, which cannot execute these Go services.

## What starts

Database migrations run before the application. A process supervisor starts the
original NATS event bus, gameplay node, API, WebSocket gateway, Next.js server, and
Caddy front door. Only Caddy listens publicly. Backend and event ports bind to
loopback. If any required child exits, the container exits so the platform can
restart the complete unit. Termination signals reach all children.

Render supplies `RENDER_EXTERNAL_URL` for the site's origin. Session secrets are
generated by Render and the private database connection is injected automatically.
No real secrets belong in GitHub. `/healthz` checks API/database readiness; the
startup sequence also waits for every application component before exposing Caddy.
This configuration is for one instance; do not enable horizontal scaling.

## Trial limits

- Free web services sleep after 15 minutes without inbound traffic. Waking can
  take approximately a minute. Restarts interrupt matches in progress.
- Free Postgres has 1 GB storage, no managed backups, and **expires after 30 days**.
  Upgrade or export/migrate before expiration to retain accounts and game data.
- Free compute is shared and memory constrained. Treat this as a small trial;
  measure memory and load before opening a larger public beta.
- Included build time, bandwidth, and free instance hours apply across the workspace.

## Playable content and sign-in

Guest login works without Google/Discord OAuth credentials. Registered sign-in
requires your own provider client ID/secret in Render, with callback URLs at
`https://YOUR-SITE/api/auth/google/callback` and
`https://YOUR-SITE/api/auth/discord/callback`.

The original backend seeds missing built-in maps from the bundled **sample** world
dataset. These are not a full production map catalogue; panorama availability can
change. Existing imported maps are preserved. Optional risk analysis, Discord bot,
and donation integrations are not started/configured by this Blueprint.

Before public release, review the operator-specific privacy/terms/contact pages.
The upstream AGPL licence and source link remain in the application.

## Deployment

Import `render.yaml` from the main branch as a Render Blueprint. Review its plan:
one Free Docker web service and one Free Postgres database, with no paid compute
or persistent disk. Apply the plan only after review. Later pushes redeploy the
application automatically if Blueprint auto-sync remains enabled.

Verify `/healthz`, `/api/bootstrap`, guest login, a solo match, and a two-browser
live match after the build becomes live. A successful YAML check alone is not
proof that a deployment is running.
